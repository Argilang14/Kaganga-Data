# Kaganga v2.3.1

Tanggal rilis: 31 Oktober 2026.

## Perubahan Utama

- Data Asrama tersedia di Informasi Umum, dengan halaman terpisah untuk gedung, kamar, penghuni, penugasan wali, riwayat, dan penempatan. Pindah Asrama ditambahkan pada pemilih konteks kanan atas tanpa mengganti kelas akademik murid.
- Penempatan kamar dan penugasan wali terhubung dengan cakupan pengasuhan. Akses data pribadi tetap mengikuti sekolah, izin, dan penugasan; memilih asrama tidak memberikan hak akses tambahan.
- Riwayat Rapor menyediakan filter Tahun Pelajaran, Semester, dan Kelas yang terpisah. Nama kelas mengikuti data kelas pada periode tersebut. Tautan lama berdasarkan ID kelas tetap didukung.
- Rapor sekolah, asrama, dan martikulasi dapat diperiksa dari riwayat pendidikan. Pemeriksaan sumber mencegah penggunaan nilai dari kelas, murid, atau periode yang tidak cocok.
- Pratinjau dan finalisasi PDF menyimpan snapshot identitas, nilai, dan penandatangan yang sudah dikonfirmasi. Revisi menerbitkan versi baru tanpa menimpa PDF final sebelumnya. Pratinjau massal dibatasi pada satu kelas dan periode.
- Rapor martikulasi memakai template yang sudah tersedia dan tahap Akhir program. Finalisasi memerlukan delapan aspek penilaian serta level penempatan lengkap; tidak menerbitkan atau mengubah nomor STTM.
- Manajemen Pengguna menambahkan izin baca, finalisasi, revisi, dan pratinjau massal arsip rapor. Persetujuan finalisasi/revisi/massal memerlukan delegasi eksplisit untuk akun nonadmin.
- Impor Data Pegawai mendukung CSV Guru/Tendik Setara dengan pratinjau pencocokan NIP/NIK, deteksi konflik, serta pilihan mengimpor hanya baris valid. Template XLSX lama tetap didukung. Impor tidak membuat ulang akun, jadwal, foto, atau penugasan.
- Backup riwayat mencakup database dan berkas PDF final/revisi di luar SQLite, dengan pemeriksaan ukuran dan checksum.

## Sebelum Memperbarui

1. Buat backup database **PC server sekolah** beserta seluruh foto, lampiran, dan PDF arsip. Backup laptop pengembang bukan pengganti backup sekolah.
2. Pastikan hanya satu server produksi menggunakan database tersebut. Selesaikan pekerjaan yang sedang berjalan dan tutup aplikasi lama sebelum pemasangan.
3. Unduh `KagangaSetup-v2.3.1.exe` melalui Pengaturan > Cek Update atau halaman Releases. Pasang pada lokasi instalasi yang sama.
4. Installer mempertahankan AppId, port produksi 1206, dan direktori data Kaganga-data. Jangan mengganti database sekolah dengan database awal dari paket.
5. Setelah pembaruan, periksa jumlah murid/pegawai, kelas aktif, absensi, pengasuhan, dan pratinjau PDF. Muat ulang browser client bila tampilan lama masih tersimpan.
6. Data gedung/kamar dan penugasan asrama perlu diisi operator. Pembaruan tidak membuat penempatan murid secara otomatis.

## Batasan

- Tidak menghubungkan Kaganga langsung ke Setara atau SIAP SR. Impor CSV tetap memerlukan file dan pemeriksaan operator.
- Rapor lama hanya dapat dibentuk bila identitas, riwayat, dan nilai sumber masih cocok. Snapshot nama kelas saja tidak dianggap cukup untuk memulihkan rapor.
- Nilai dan data sumber tetap dapat disunting sesuai izin. PDF final yang sudah disimpan tetap beku; koreksi dokumen menggunakan revisi.
- Tahap martikulasi merupakan hasil program tahunan pada kelas sumber, bukan nilai tengah semester atau salinan otomatis ke semester lain.
- Data operasional, CSV pribadi, foto, lampiran, konfigurasi lokal, token sesi, dan screenshot QA tidak disertakan pada repositori atau paket instalasi.
- Installer belum ditandatangani sertifikat penerbit tepercaya. Windows dapat menampilkan peringatan penerbit.
- Instalasi dependensi produksi melaporkan 22 temuan keamanan npm: 1 rendah, 10 sedang, dan 11 tinggi. Penilaian keterpaparan serta pembaruan dependensi tersebut belum termasuk rilis ini; rilis ini tidak dinyatakan bebas kerentanan.
- Pemeriksaan Svelte masih memuat 116 warning lama. Lint file perubahan memuat 8 temuan lama pada modul pegawai, yang juga terdapat pada kode v2.3.0; tidak ada temuan baru pada file tambahan.
- Pemasangan pada PC sekolah, kamera, jaringan sekolah, dan cetak fisik tetap perlu diperiksa operator. Pengujian otomatis memakai database salinan.

## Pengujian

- Build produksi berhasil; 379 unit test lulus; pemeriksaan Svelte 0 error.
- Database salinan asrama: 15 pemeriksaan lulus, termasuk kapasitas kamar, histori penempatan, cakupan wali, batas sekolah, serta keutuhan kelas dan data akademik.
- UI asrama: 15 pemeriksaan lulus, termasuk halaman terpisah, dialog, keyboard, mode gelap, dan viewport 320-1920px.
- Arsip rapor sekolah/asrama: 11 pemeriksaan layanan dan 10 pemeriksaan UI lulus, termasuk pratinjau, finalisasi, revisi, konflik persetujuan, akses akun, serta backup dan pemulihan PDF.
- Martikulasi: 7 pemeriksaan integrasi lulus, termasuk sumber nilai, penolakan finalisasi belum lengkap, PDF nyata, revisi, manifest backup, dan API dokumen.
- Filter riwayat rapor: 8 pemeriksaan lulus, termasuk tautan kelas lama, pergantian tahun/semester, parameter tidak sah, dan viewport 360-1440px.
- Impor pegawai: fixture sintetis lulus untuk pratinjau, impor ulang tanpa duplikasi, rollback transaksi, batas sekolah, dan dialog responsif. Data CSV pribadi tidak diperlukan untuk uji rilis ini.
- Runtime paket Windows lulus skenario database awal dan upgrade dari database salinan: startup, migrasi, login, integrity check, foreign key check, serta menu asrama dan riwayat rapor. Pengujian ini tidak menjalankan pemasangan GUI pada PC sekolah.
- Database dalam paket terverifikasi berisi 0 sekolah, murid, pegawai, penghuni asrama, arsip rapor, dan sesi pengguna operasional.
