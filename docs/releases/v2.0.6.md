# Kaganga v2.0.6

Tanggal rilis: 15 Agustus 2026

## Ringkasan perubahan

- Menambahkan fondasi Surat Menyurat untuk SPPD dan Dinas Luar dengan pemisahan data per sekolah.
- Menyempurnakan detail, edit, foto, template, impor, dan ekspor Data Pegawai.
- Memperbaiki formulir edit Data Murid agar kembali dapat dibuka dan disimpan.
- Menyempurnakan impor dan ekspor Data Mata Pelajaran.
- Menghubungkan Jurnal Mengajar dengan konteks jadwal, kelas, mata pelajaran, dan jenis jadwal.
- Menambahkan cetak Jurnal Mengajar per kelas atau per mata pelajaran, pilihan penandatangan, kop dua logo, dan tabel multipage.
- Membatasi cetak jurnal berdasarkan sekolah dan penugasan admin, wali kelas, atau guru mata pelajaran.
- Menyempurnakan target JP mingguan agar dihitung per kelas dan per jenis jadwal.
- Memperkuat pemeriksaan, backup, dan pemulihan database SQLite saat pembaruan aplikasi.
- Menyeragamkan nama produk dan installer menjadi Kaganga.

## Catatan migrasi dari v2.0.5

1. Installer mempertahankan `AppId` v2.0.5 sehingga dijalankan sebagai pembaruan pada instalasi Kaganga yang sama.
2. Data aktif tetap berada di `%LOCALAPPDATA%\Kaganga-data`; installer tidak menimpa database sekolah dengan database kosong.
3. Starter membuat backup `database-backup-before-2.0.6-*.sqlite3` sebelum migrasi pertama versi ini.
4. Penyesuaian tabel jurnal, pegawai, jadwal target JP, dan surat menyurat dilakukan idempoten saat aplikasi dimulai.
5. Direktori lama `%LOCALAPPDATA%\Rapkumer-data` hanya dipakai sebagai sumber migrasi jika database Kaganga belum tersedia.
6. Bila pembaruan gagal, tutup Kaganga dan pulihkan database dari backup pra-rilis atau backup otomatis sebelum 2.0.6.

## Validasi rilis

- Database produksi dibackup sebelum build dan lolos `PRAGMA integrity_check` serta `foreign_key_check`.
- Unit test jurnal, jadwal, pegawai, dan keamanan database dijalankan sebelum packaging.
- `pnpm check` selesai tanpa error dan build produksi berhasil.
- Instalasi baru v2.0.6 berhasil dan runtime hasil instalasi mengembalikan HTTP 200 pada port uji terisolasi.
- Pembaruan installer nyata dari `rapkumer@2.0.5` ke `kaganga@2.0.6` berhasil pada lokasi uji yang sama.
- Hash database produksi sebelum dan sesudah uji installer tetap identik; aplikasi hasil instalasi hanya dijalankan dengan database uji terisolasi.
